00c07110  FAILED (about 20 compiles + a 800-variant search of statement orders): CHeroPathfinder::InitStartNode draft has the right size (151 bytes) and the same instruction set, but the compiler schedules the stores differently. What was learned: (1) the node flags are bit fields (b1 = bit 1, g3 = bits 3..8, b0/b2/b9/g24 = bits 0,2,9,24..25, counter = bits 15..22, b26 = bit 26), and VC merges all constant bit-field assignments into one read-modify-write unless something that may alias intervenes (a load through `this`, or an inline member call); the original keeps four separate flag operations (xor-form for bit 1, `and [mem]` for bits 3..8, a register `and`/`or dh,2` group, `and [mem]` for bits 15..22+26). Wrapping the groups in inline member functions of the flags struct reproduces that grouping. (2) What is left is the order of `moved = 0`, the cost stores and the flag operations around `setz`: the exe computes `m_settings.m_24 == 1` first, then stores moved, then does the flag xor; every source order tried gives the zero register in a different place.
